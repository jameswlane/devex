# Configuration Validation

`devex config validate` recursively checks YAML files in the default configuration tree at `~/.local/share/devex/config/`:

```bash
devex config validate
devex config validate --strict
```

The command checks the `applications/`, `environments/`, `system/`, and optional `desktop/` directories. It also checks YAML syntax in existing `dotfiles.yaml`, `security.yaml`, and init metadata. When a canonical directory has no YAML files, the summary falls back to the corresponding legacy monolithic file if one exists.

## What validation checks

- YAML syntax in nested files.
- Required application `name` and `description` fields.
- A platform or `all_platforms` installation configuration.
- Installation methods and required installation commands. A `curlpipe` configuration may instead provide a download URL.
- Basic environment, system, and desktop configuration checks.

Categories are free-form labels. Supported methods used by the shipped catalog do not produce warnings. Strict mode requires the `system/` directory during directory content validation. Validation errors return a nonzero exit status; warnings are reported separately.

## Find the file to fix

```bash
devex config show --detailed
devex config edit applications
devex config validate
```

Errors identify the relative file and field, for example `Required field missing in development/git.yaml.name`. Application files contain one application at the YAML root; an `applications:` wrapper belongs to the legacy monolithic format.

`config show` reports file sizes, modification times, and syntax status for each directory. Its syntax status does not replace content validation. The `--fix` option currently reports that automatic fixes are not implemented; correct the reported files manually.

## Verify loaded applications

```bash
devex list available
devex list available --search docker
```

For configuration locations, precedence, and legacy migration, see the [configuration overview](/configuration).
