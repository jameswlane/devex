# devex inventory

`devex inventory` exports the applications DevEx manages on a machine, with the manager, packages and versions the native package manager reports, and reconciles DevEx's records with what is actually installed. It changes nothing.

```bash
devex inventory [--format table|json|yaml] [--include-hostname] [--check]
```

## What is reported

For every application DevEx tracks:

| Field | Meaning |
| --- | --- |
| `name` | The application |
| `manager` | Its install method, from the definition DevEx recorded at install time |
| `packages` | The native package identifiers that method installed (installation options such as `--classic` are left out) |
| `version` | The version the package manager reports now |
| `state` | `installed`, `missing` (the package manager reports it is not installed) or `unknown` (it could not be checked; `detail` says why) |
| `managed_by` | Always `devex` |
| `definition_recorded` | Whether DevEx recorded the definition when it installed the application |

Versions come from `dpkg-query` for apt and deb packages, `snap list` and `flatpak info`. Other methods (mise, curlpipe, Docker, ...) are reported as `unknown`. For applications installed by DevEx versions that did not record definitions, the current catalog definition is used and the drift entry says so.

An application is `missing` only when its package manager answers that the package is not installed. When the check itself fails (the manager is not on `PATH`, snapd is unreachable, a permission error), the application is `unknown` with the error in `detail`, and no drift is reported. Applications installed from a downloaded `.deb` file or URL are `unknown`: DevEx does not record the dpkg package name such a file installs, so it cannot be checked. If the command is canceled or times out, it fails instead of printing a partial export.

## Drift

`drift` lists differences: `missing` for tracked applications that are no longer installed, and `no_definition` for records without a definition (reinstall the application with `devex install` to record one). `--check` exits nonzero when there is drift, for use in automation.

## Machine identity

`machine.id` is a salted SHA-256 of `/etc/machine-id`, so exports from the same machine match without revealing its machine-id. The hostname is included only with `--include-hostname`. `machine` also lists the OS and architecture.

## Ingestion

The JSON and YAML output has `schema_version: devex.inventory/v1`; fields are only added, never renamed, within v1. Collect it from each machine, for example:

```bash
devex inventory --format json > "inventory-$(date +%F).json"
# or in a fleet: devex remote install … then
ssh devbox devex inventory --format json | jq '.items[] | {name, version, state}'
```
