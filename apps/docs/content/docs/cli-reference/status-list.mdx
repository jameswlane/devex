# devex status & list

The `status` and `list` commands provide essential information about your development environment. Use `status` to check what's installed and working, and `list` to browse available applications and discover new tools.

## devex status

Check the installation status of applications in your development environment.

### Usage

```bash
devex status [flags]
```

### Options

| Flag | Short | Type | Default | Description |
|------|-------|------|---------|-------------|
| `--format` | `-f` | `string` | `table` | Output format (table, json, yaml, csv) |
| `--category` | `-c` | `string` | `all` | Filter by category |
| `--verbose` | `-v` | `bool` | `false` | Show detailed information |
| `--check-updates` | `-u` | `bool` | `false` | Check for available updates |
| `--problems-only` | `-p` | `bool` | `false` | Show only problematic installations |

## devex list

Browse and discover available applications that can be installed with DevEx.

### Usage

```bash
devex list [flags]
```

### Options

| Flag | Short | Type | Default | Description |
|------|-------|------|---------|-------------|
| `--category` | `-c` | `string` | `all` | Filter by category |
| `--search` | `-s` | `string` | | Search by name or description |
| `--installed` | `-i` | `bool` | `false` | Show only installed applications |
| `--available` | `-a` | `bool` | `false` | Show only available (not installed) applications |
| `--format` | `-f` | `string` | `table` | Output format (table, json, yaml, list) |
| `--platform` | `-p` | `string` | `auto` | Filter by platform (linux, macos, windows) |
| `--detailed` | `-d` | `bool` | `false` | Show detailed information |

## devex detect

Detect the technologies a project uses (languages, frameworks, build tools and infrastructure), and turn them into DevEx application suggestions. For the operating system, distribution and package managers, use `devex platform`.

Detection runs the `tool-stackdetector` plugin. DevEx downloads it the first time a detect command runs (not with `--offline`; install it beforehand with `devex plugin install tool-stackdetector`). Detection only reads the project directory.

### Usage

```bash
devex detect [directory] [flags]
devex detect analyze [directory] [flags]
devex detect suggest [directory] [flags]
devex detect apply [directory] [flags]
```

The directory defaults to the current directory.

| Command | What it does |
|---------|--------------|
| `devex detect` | Lists detected technologies with their category and confidence |
| `devex detect analyze` | Adds declared dependencies, project size, issues and the plugin's recommendations |
| `devex detect suggest` | Maps detected technologies to DevEx applications; already-configured ones are marked `configured` |
| `devex detect apply` | Adds the suggested applications and their dependencies to your configuration, like `devex add` |

### Options

| Flag | Commands | Default | Description |
|------|----------|---------|-------------|
| `--format` | all | `table` | `table` or `json` |
| `--confidence` | all | `0.5` | Minimum confidence, from `0.0` to `1.0` (the plugin scores 1-10) |
| `--category` | all | | Only technologies in this category, for example `Language`, `Framework`, `Containerization` |
| `--detailed` | `detect` | `false` | Show the files that identified each technology |
| `--output` | `detect` | | Also save the JSON result to this file |
| `--dry-run` | `apply` | `false` | Show what would be added without changing configuration |
| `--yes`, `-y` | `apply` | `false` | Add without prompting; required without a terminal |

### Suggestions

Frameworks and tools map to the runtime they need: React, Next.js, Vite and similar map to Node.js; Poetry and Pipenv projects map to Python; Maven and Gradle map to Java; Docker Compose maps to Docker; Make and CMake map to Build Essential. Technologies without a DevEx application (for example PHP) are reported but not suggested.

### Applying suggestions

`devex detect apply` shows the applications first, then backs up your configuration and validates each addition like `devex add`. It changes configuration only; run `devex install` afterwards. Applications already in your configuration are skipped, so running it again makes no changes.

```bash
# Preview
devex detect apply --dry-run

# Add only high-confidence suggestions without prompting
devex detect apply --confidence 0.8 --yes

# Then install them
devex install
```

### JSON output

```bash
devex detect --format json
```

```json
{
  "project_path": "/home/me/src/service",
  "summary": { "primary_language": "Go", "project_type": "Web Application" },
  "technologies": [
    { "name": "Go", "category": "Language", "confidence": 10, "files": ["go.mod"] },
    { "name": "Docker", "category": "Containerization", "confidence": 8, "files": ["Dockerfile"] }
  ]
}
```

`devex detect suggest --format json` returns `[{"app", "category", "description", "confidence", "technologies", "configured"}]`, and `devex detect apply --format json` returns `{"added", "skipped", "dry_run"}`.

### Plugin protocol

The CLI runs `tool-stackdetector report --format json <directory>` and reads the report from the plugin's stdout; the plugin writes progress to stderr. The report has `project_path`, `technologies` (`name`, `category`, `confidence` 1-10, `description`, `files`), `dependencies`, `project_size`, `recommendations`, `issues` and `summary`.

## Integration Examples

### Scripting with Status Commands

```bash
#!/bin/bash
# Check if required tools are installed

required_apps=("git" "docker" "node")
missing_apps=()

for app in "${required_apps[@]}"; do
    if ! devex status --format json | jq -r ".applications[] | select(.name == \"$app\" and .status == \"installed\") | .name" | grep -q "$app"; then
        missing_apps+=("$app")
    fi
done

if [ ${#missing_apps[@]} -ne 0 ]; then
    echo "Missing required applications: ${missing_apps[*]}"
    echo "Installing missing applications..."
    devex add "${missing_apps[@]}" --install
fi
```

### Monitoring and Alerting

```bash
# Check for problems and send alerts
problems=$(devex status --problems-only --format json)
if [ "$problems" != "[]" ]; then
    echo "$problems" | mail -s "DevEx Issues Detected" admin@company.com
fi

# Check for updates weekly
if [ "$(date +%u)" -eq 1 ]; then  # Monday
    updates=$(devex status --check-updates --format json)
    if [ "$updates" != "[]" ]; then
        echo "Updates available: $updates"
    fi
fi
```
