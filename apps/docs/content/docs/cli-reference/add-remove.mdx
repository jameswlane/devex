# devex add & remove

The `add` and `remove` commands allow you to dynamically modify your development environment by adding new applications or removing existing ones. These commands provide both interactive and non-interactive modes for managing your software installations.

## devex add

Add new applications to your development environment configuration and optionally install them immediately.

### Usage

```bash
devex add [application...] [flags]
```

### Options

| Flag | Short | Type | Default | Description |
|------|-------|------|---------|-------------|
| `--install` | `-i` | `bool` | `false` | Install immediately after adding to config |
| `--category` | `-c` | `string` | | Filter applications by category (with `--custom`: the new tool's category, default `development`) |
| `--search` | `-s` | `string` | | Search applications by name or description |
| `--interactive` | | `bool` | `true` | Use interactive selection mode |
| `--force` | | `bool` | `false` | With `--custom`: replace an existing definition of the same name (backed up first) |
| `--yes` | `-y` | `bool` | `false` | Accept the preview without asking |
| `--custom` | | `bool` | `false` | Define a tool that is not in the catalog, see [Custom tools](#custom-tools) |
| `--description` | | `string` | | With `--custom`: description of the tool |
| `--<platform>-method` | | `string` | | With `--custom`: install method for `linux`, `macos`, `windows` or `all` (all platforms) |
| `--<platform>-package` | | `string` | | With `--custom`: package identifier for that platform |
| `--<platform>-pre-install` | | `string` (repeatable) | | With `--custom`: shell command to run before installing on that platform |
| `--<platform>-post-install` | | `string` (repeatable) | | With `--custom`: shell command to run after installing on that platform |
| `--dry-run` | `-n` | `bool` | `false` | Show what would be added without executing |

### Custom tools

A tool that is not in the catalog can be defined with `--custom`. DevEx writes a complete
cross-platform definition to your user configuration (`~/.local/share/devex/config/applications/<category>/<name>.yaml`)
and never runs a package manager while doing so. Install it afterwards with `devex install <name>`.

```bash
# 1. Preview the YAML. Nothing is written.
devex add mytool --custom \
  --description "Internal build helper" \
  --category development \
  --linux-method apt   --linux-package mytool \
  --linux-pre-install  "mkdir -p \$HOME/.mytool" \
  --linux-post-install "mytool --version" \
  --macos-method brew  --macos-package acme/tap/mytool \
  --windows-method mise --windows-package mytool \
  --dry-run

# 2. Write it. Unattended runs need --yes; a terminal asks you to confirm instead.
devex add mytool --custom ... --yes
```

The preview shows the exact file that will be written:

```yaml
name: mytool
description: Internal build helper
category: development
default: false
linux:
    install_method: apt
    install_command: mytool
    uninstall_command: mytool
    pre_install:
        - shell: mkdir -p $HOME/.mytool
    post_install:
        - shell: mytool --version
macos:
    install_method: brew
    install_command: acme/tap/mytool
    uninstall_command: mytool
windows:
    install_method: mise
    install_command: mytool
    uninstall_command: mytool
```

**Rules**

- **Methods**: only install methods that have a DevEx package-manager plugin and run on that platform are accepted.
  An unknown, planned (no plugin yet) or wrong-platform method is rejected with the list of supported methods.
  Download methods (`curlpipe`, `appimage`) need checksum verification, which flags cannot express; write those in the YAML directly.
- **Packages**: `--<platform>-package` is a single identifier and is stored as `install_command`. Whitespace, a leading `-`
  and shell characters (`; | & $ \` ( ) < >` and quotes) are rejected, so a package name can never smuggle in an argument or a command.
  Put anything else in a hook.
- **Hooks**: `--<platform>-pre-install` and `--<platform>-post-install` can be repeated and run in order. They are checked with the same
  command policy used at install time (`security.yaml` level and overrides), so a hook that would be refused later is refused now.
  Hooks are kept as separate `shell:` entries; the package name is never interpolated into them.
- **Platforms**: define any of `linux`, `macos`, `windows`, or `all` (written as `all_platforms`, which takes precedence).
- **Prompts**: with a terminal attached, `devex add --custom` asks for anything the flags left out (name, description, category,
  platforms, method, package and optional hooks) and re-asks when a value is invalid. In CI or with `--format json` it never prompts
  and reports what is missing.
- **Existing definitions are preserved**: if a tool with that name is already configured, or exists in the catalog, the command stops.
  `--force` replaces it (as a user override) after the whole configuration tree is backed up under `~/.local/share/devex/backups`;
  restore it with the usual `devex config` backup commands.

## devex remove

Remove applications from your development environment configuration with intelligent dependency checking.

### Usage

```bash
devex remove [application...] [flags]
```

### Options

| Flag | Short | Type | Default | Description |
|------|-------|------|---------|-------------|
| `--uninstall` | `-u` | `bool` | `false` | Uninstall from system after removing from config |
| `--force` | `-f` | `bool` | `false` | Remove even if other apps depend on it |
| `--backup` | `-b` | `bool` | `true` | Create backup before removal |
| `--interactive` | | `bool` | `true` | Use interactive selection mode |
| `--dry-run` | `-n` | `bool` | `false` | Show what would be removed without executing |

### Dependency Safety

<Callout type="warn">
DevEx automatically analyzes dependencies before removal to prevent breaking your environment. Applications with dependents are marked with warnings and require explicit confirmation.
</Callout>

### Dependency Management

DevEx analyzes three types of dependencies:

#### Direct Dependencies
Applications that explicitly require the target application:

```yaml
applications:
  development:
    - name: docker-compose
      dependencies:
        - docker  # Direct dependency
```

#### System Dependencies
Applications that rely on system-level integration:

```
kubectl → docker (for local Kubernetes clusters)
VS Code → git (for version control features)
npm packages → node (runtime requirement)
```

#### Optional Dependencies
Applications that enhance functionality but aren't required:

```
Postman → Chrome (for OAuth flows, optional)
VS Code → Python (for Python development, optional)
```

### Removal Strategies

<Tabs items={['Conservative', 'Aggressive', 'Selective', 'Bulk']}>
  <Tab value="Conservative">
    **Conservative Removal**: Only remove applications with no dependencies
    
    ```bash
    # Check what's safe to remove
    devex remove --dry-run --safe-only
    
    # Remove only applications without dependents
    devex remove slack postman chrome
    ```
  </Tab>
  
  <Tab value="Aggressive">
    **Aggressive Removal**: Remove everything, handling dependencies
    
    ```bash
    # Remove with cascade (removes dependents too)
    devex remove docker --cascade
    
    # Force remove core dependencies
    devex remove git --force --cascade
    ```
  </Tab>
  
  <Tab value="Selective">
    **Selective Removal**: Choose specific applications with dependency resolution
    
    ```bash
    # Interactive dependency resolution
    devex remove docker  # Will prompt about dependents
    
    # Remove and replace dependencies
    devex remove docker --replace-with=podman
    ```
  </Tab>
  
  <Tab value="Bulk">
    **Bulk Removal**: Remove entire categories
    
    ```bash
    # Remove all optional applications
    devex remove --category optional
    
    # Remove unused applications
    devex remove --unused
    
    # Remove applications not used in 30 days
    devex remove --unused --days=30
    ```
  </Tab>
</Tabs>

## devex uninstall

Uninstall applications from the system without removing them from your DevEx configuration:

```bash
devex uninstall --app docker --force
devex uninstall --apps "git,docker,node" --force
devex uninstall --category "Development Tools" --force
```

DevEx uses the application definition saved at install time for inline applications. For older installations that only recorded an application name, it restores the install method, dependencies, and cleanup metadata from the current application catalog, including inline definitions passed with `--config`. Pass the original configuration when uninstalling older inline applications if no definition was saved. Saved definitions take precedence over current configuration.

Applications installed outside DevEx can be uninstalled only when their names exist in the current application catalog. DevEx cannot infer package-manager commands for arbitrary software that it did not install and that is not in the catalog; unknown names return an error without attempting removal. Use the same package manager that installed such software instead.

The command processes all requested applications and returns a nonzero exit code if any application cannot be resolved or uninstalled. In automation, use `--force` to suppress confirmation prompts and check the exit status.

Category names match case-insensitively against resolved application definitions, so use the full category name, such as "Development Tools". Category selection skips applications known to belong to another category. If a tracked application's definition cannot be resolved and its category is unknown, the command warns and leaves it installed without failing the category operation. Restore its saved definition or pass its original configuration to resolve it, or select it explicitly with `--app` to diagnose the error. Resolution failures for applications known to belong to the requested category still return a nonzero exit code.

Currently, `--cascade` allows noncritical dependency conflicts but does not add dependent applications to the removal list. Select dependents explicitly with `--apps` when removing them. `--remove-orphans` runs the package manager's orphan cleanup after at least one successful removal.

### Clear a stuck uninstall record

If you remove an application outside DevEx, `devex uninstall --app <app>`
clears its tracking record and saved definition when the plugin confirms that
it is absent. A failed installed-check keeps those records: a query failure
cannot establish that a package is gone, including partially removed
multi-package applications.

If the check keeps failing, explicitly forget the application:

```bash
# Preview exactly which DevEx records will be cleared
devex uninstall --forget docker --dry-run

# Clear only the tracking record and saved installation definition
devex uninstall --forget docker

# Skip confirmation
devex uninstall --forget docker --force
```

`--forget <app>` never calls or bootstraps a package-manager plugin and never
runs native removal, stops services, removes dependencies, or deletes
configuration or user data. It works even if the saved definition is missing
or damaged. Any packages still present remain installed.

Interactive use asks for confirmation with a default of no. `--force`,
`--non-interactive`, `DEVEX_NONINTERACTIVE=true`, and CI mode skip that prompt.
`--dry-run` previews without changing records or prompting. Unknown or
untracked applications return an error. Use the tracked application name;
`--forget` cannot be combined with other uninstall selection or cleanup flags.

### Undo Support

Both commands support undo operations:

```bash
# View recent changes
devex config undo list

# Undo last add operation
devex config undo last

# Undo specific operation
devex config undo operation "add docker vscode"

# Undo with confirmation
devex config undo operation 3 --confirm
```

## Advanced Usage

### Custom Application Definitions

Add custom applications not in the default catalog with `devex add NAME --custom`; see [Custom tools](#custom-tools) for the flags and a complete example.

### Bulk Operations

Perform operations on multiple applications:

```bash
# Add entire development stack
devex add @full-stack  # Uses predefined template

# Remove development tools except essentials
devex remove --category development --except git,curl

# Add applications matching pattern
devex add "*code*"  # Adds vscode, code-server, etc.

# Remove unused applications
devex remove --cleanup --unused
```

### Integration with Templates

Add/remove commands work with configuration templates:

```bash
# Add applications from template
devex template apply backend-team
devex add --from-template backend-team

# Remove applications not in template
devex remove --not-in-template backend-team

# Sync with team template (add missing, remove extra)
devex add --sync-template backend-team
```
