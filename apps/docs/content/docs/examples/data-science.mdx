# Data Science

The built-in `data-science` lifecycle template runs JupyterLab and MLflow in Docker containers. It never touches your system Python or R. Notebooks and tracking data live in named Docker volumes.

```bash
devex template info data-science
devex init --profile data-science   # optional: record the profile in ~/.devex
```

## Components

| Input | Default | Choices |
| --- | --- | --- |
| `components` | `jupyter` | `jupyter`, `mlflow` |
| `notebook_stack` | `scipy` | `scipy` (Python), `r` (R), `datascience` (Python, R and Julia) |
| `jupyter_tag` | `lab-4.6.6` | Any [Jupyter Docker Stacks](https://jupyter-docker-stacks.readthedocs.io/) tag |
| `mlflow_version` | `v3.18.0` | Any `ghcr.io/mlflow/mlflow` tag |
| `jupyter_port` / `mlflow_port` | `8888` / `5000` | Ports published on 127.0.0.1 |
| `jupyter_name` / `mlflow_name` | `devex-jupyter` / `devex-mlflow` | Container names |

The notebook image is `quay.io/jupyter/<notebook_stack>-notebook:<jupyter_tag>`. MLflow stores runs in SQLite and keeps artifacts in the `devex-mlflow-data` volume.

## Install

```bash
# Python notebook only
devex install --template data-science --non-interactive

# R notebook and MLflow tracking
devex install --template data-science \
  --answer components=jupyter,mlflow \
  --answer notebook_stack=r \
  --non-interactive

# Jupyter's login token (drop sudo once you log in again)
sudo docker logs devex-jupyter 2>&1 | grep token=
```

Open JupyterLab at http://127.0.0.1:8888 and MLflow at http://127.0.0.1:5000. In a notebook, set `MLFLOW_TRACKING_URI=http://host.docker.internal:5000` (Docker Desktop) or use the host's bridge address (Linux).

## Limits

<Callout type="info">
Docker Engine is installed only on Linux. On macOS, start Docker Desktop before you install; its license terms apply.
</Callout>

- **First install on a machine without Docker**: the Docker Engine step adds you to the `docker` group, but a running session doesn't pick up new groups. Until you log out and back in, DevEx runs the container steps with sudo.
- GPU access is not configured.
- Ports are published on 127.0.0.1 only.
- `remove` deletes the containers but keeps the `devex-jupyter-work` and `devex-mlflow-data` volumes, so your work survives a reinstall. Delete them with `docker volume rm`.

## Maintain, status and remove

`maintain` pulls the exact image recorded at install time, then restarts the container. To move to a newer image, reinstall with a new `jupyter_tag` or `mlflow_version`.

```bash
devex status --template data-science --run latest
devex maintain --template data-science --run latest
devex remove --template data-science --run latest --force
```

## Smoke procedure

Run this on a fresh Debian or Ubuntu VM:

```bash
devex template validate data-science
devex template plan data-science --action install --answer components=jupyter,mlflow --non-interactive --format yaml
devex install --template data-science --answer components=jupyter,mlflow --non-interactive --dry-run
devex install --template data-science --answer components=jupyter,mlflow --non-interactive

curl -fsS http://127.0.0.1:8888/api && echo " jupyter ok"
curl -fsS http://127.0.0.1:5000/health && echo mlflow ok

devex status --template data-science --run latest
devex remove --template data-science --run latest --force
```
