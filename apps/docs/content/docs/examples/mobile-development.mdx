# Mobile Development

The built-in `mobile` lifecycle template installs the command-line prerequisites for React Native, Flutter, Android and iOS. You pick the targets. Every step has an explicit OS guard, so DevEx installs only what works on the current platform.

```bash
devex template info mobile
devex init --profile mobile   # optional: record the profile in ~/.devex
```

## Targets

| Target | Linux | macOS | What it installs |
| --- | --- | --- | --- |
| `react-native` | Yes | Yes | Node.js and a JDK through mise |
| `flutter` | Yes | Yes | The Flutter SDK through mise |
| `android` | Yes (Flatpak) | Yes (Homebrew cask) | A JDK through mise, plus Android Studio |
| `ios` | No: nothing is installed | Yes (Homebrew formula) | CocoaPods |

React Native and Flutter Android builds also need `android`. iOS builds also need `ios` on macOS.

You must choose at least one target: `targets` is required, so a non-interactive install without it fails instead of installing everything.

## Versions

| Input | Default | Notes |
| --- | --- | --- |
| `node_version` | `24` | Any mise version prefix for `node` |
| `java_version` | `temurin-17` | Any mise `java` version; Android Gradle builds need JDK 17 or newer |
| `flutter_version` | `3.50` | Any mise version prefix for `flutter` |

## Install

```bash
# React Native for Android on Linux
devex install --template mobile \
  --answer targets=react-native,android \
  --non-interactive

# Flutter for Android and iOS on macOS, with a pinned SDK
devex install --template mobile \
  --answer targets=flutter,android,ios \
  --answer flutter_version=3.50 \
  --non-interactive
```

## Limits that DevEx cannot automate

<Callout type="warn">
These steps need you at the keyboard, or a license only you can accept. The template never attempts them.
</Callout>

- **Xcode**: install it from the App Store, then run `sudo xcodebuild -license accept` and `xcode-select --install`.
- **Android SDK and licenses**: the Android Studio first-run wizard downloads the SDK, platform tools and emulator images. It needs a desktop session. Accept the SDK licenses there, or with `sdkmanager --licenses`.
- **Homebrew**: the macOS steps use Homebrew and do not install it.
- **iOS on Linux**: the `ios` target installs nothing on Linux.

## Maintain, status and remove

These actions use the resources recorded by the install. They need no answers.

```bash
devex status --template mobile --run latest
devex maintain --template mobile --run latest   # re-resolves the mise versions; brew upgrade on macOS
devex remove --template mobile --run latest --force
```

On Linux, Android Studio is not updated by `maintain`. Run `flatpak update com.google.AndroidStudio` yourself, because a plain `flatpak update` would update every Flatpak on the machine.

## Smoke procedure

Run this on a fresh Debian or Ubuntu VM, or on a macOS machine with Homebrew:

```bash
devex template validate mobile
devex template plan mobile --action install --answer targets=react-native,android --non-interactive --format yaml
devex install --template mobile --answer targets=react-native,android --non-interactive --dry-run
devex install --template mobile --answer targets=react-native,android --non-interactive

mise exec -- node --version
mise exec -- java -version
flatpak info com.google.AndroidStudio   # Linux; on macOS: brew list --cask android-studio

devex status --template mobile --run latest
devex remove --template mobile --run latest --force
```
