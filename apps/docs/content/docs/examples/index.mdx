## How the examples work

The examples use two parts of DevEx:

- **The application catalog.** `devex init` writes it to `~/.local/share/devex/config`. List it with `devex list available`, and install from it by name, for example `devex install git Docker`.
- **Built-in lifecycle templates.** A template is a set of install, status, maintain and remove steps with inputs. List them with `devex template list`.

The data science, mobile, DevOps and game development examples each use one template. The web example combines catalog apps with the `web-development` and `databases` templates. The backend example combines catalog apps, mise and the `databases` and `devops` templates, because the built-in `full-stack` and `backend` templates don't install on a fresh machine yet ([#462](https://github.com/jameswlane/devex/issues/462), [#463](https://github.com/jameswlane/devex/issues/463)).

## Work with a template

```bash
# Find a template and read what it does
devex template list
devex template info databases

# Check it and see the steps an install would run
devex template validate databases
devex template plan databases --action install --answer databases=postgres --non-interactive

# Preview, then install (see the note below about Docker)
devex install --template databases --answer databases=postgres --non-interactive --dry-run
devex install --template databases --answer databases=postgres --non-interactive

# Check, update or remove what the latest install created
devex status --template databases --run latest
devex maintain --template databases --run latest
devex remove --template databases --run latest --force
```

`--answer key=value` sets one input. Put several in a YAML file and pass `--answers <file>`. `devex template info` lists a template's inputs, and the [Template Runtime](/docs/configuration/templates) page covers the schema.

To record a template's profile in your configuration, run `devex init --profile <name>`. `devex init --help` lists the profiles.

<Callout type="info">
On a fresh machine, run `devex init` before you plan a template or install catalog apps ([#466](https://github.com/jameswlane/devex/issues/466)). For templates that run containers, install Docker with `devex install Docker` before the template install ([#470](https://github.com/jameswlane/devex/issues/470)). Until you log out and back in, DevEx runs the template's `docker` commands with sudo, because your session doesn't have the new `docker` group yet.
</Callout>

## Write your own template

A template is one YAML file. Start from a built-in one in [`apps/cli/assets/templates`](https://github.com/jameswlane/devex/tree/main/apps/cli/assets/templates), then check and install it by path:

```bash
devex template validate ./my-stack.yaml
devex template plan ./my-stack.yaml --action install --non-interactive
devex install --template ./my-stack.yaml --non-interactive --dry-run
```

To share a template with the project, add it to `apps/cli/assets/templates` with a smoke procedure in its example page, and open a pull request.

## Smoke procedure

Run this on a fresh Debian 12 or Ubuntu 24.04 VM to check the commands on this page. It needs `curl`, `git` and `unzip`, and sudo for the Docker steps.

```bash
devex init --profile backend --non-interactive
devex list available
devex template list
devex template info databases
devex template validate databases
devex template plan databases --action install --answer databases=postgres --non-interactive
devex install --template databases --answer databases=postgres --non-interactive --dry-run

devex install Docker --non-interactive

devex install --template databases --answer databases=postgres --non-interactive
timeout 60 sh -c "until docker exec devex-postgres pg_isready; do sleep 2; done"

devex status --template databases --run latest
devex maintain --template databases --run latest
devex remove --template databases --run latest --force
```
