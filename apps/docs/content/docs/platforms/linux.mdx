# Linux Distributions

## Debian and Ubuntu: stable APT path

APT is DevEx's primary supported package manager. The repository includes
[APT operation tests](https://github.com/jameswlane/devex/tree/main/packages/package-manager-apt)
and [CLI container tests](https://github.com/jameswlane/devex/tree/main/apps/cli/test/e2e)
for Debian 12 and Ubuntu 24.04. This does not promise every Debian derivative or
release is tested.

Preview configured applications before installing:

```bash
devex install --dry-run
devex install --dry-run --format json
```

Review every application, dependency, update and configuration action in the
plan. Setup presents a confirmation before applying the selected plan. APT
system operations may require sudo; DevEx should not be run wholesale as root.
Optional Flatpak and Snap integrations are experimental and require suitable
host tools and repositories. They are not automatically authorized by choosing
APT.

### Databases and Docker

Choosing a database in `devex setup` adds Docker as a dependency. Setup uses the
catalog's Docker entry, and the confirmation lists everything it does: add
Docker's apt repository and signing key for Debian or Ubuntu, install Docker
Engine, enable `docker.service` and add you to the `docker` group. If a `docker`
executable already exists (for example the distribution's `docker.io`), setup
skips Docker. Each database runs as a container bound to `127.0.0.1`
(`postgres16`, `mysql8`, `redis`). If a container with that name already
exists, setup leaves it as it is. Until you log out and back in, your session
isn't in the `docker` group yet, so setup creates the containers with `sudo`.

## Other distributions: experimental

DNF and Pacman now have native command implementations; they are not merely
placeholder plugins. Broader lifecycle and platform verification remains
separate from those command tests.

| Distribution | Manager | Tracking |
| --- | --- | --- |
| Fedora / RHEL | DNF | [Lifecycle CI #121](https://github.com/jameswlane/devex/issues/121) |
| Arch | Pacman / Yay | [Lifecycle coverage #122](https://github.com/jameswlane/devex/issues/122), [Yay #107](https://github.com/jameswlane/devex/issues/107) |
| openSUSE | Zypper | [Operations #108](https://github.com/jameswlane/devex/issues/108), [Lifecycle coverage #123](https://github.com/jameswlane/devex/issues/123) |
| Alpine / Gentoo / Void / Solus / Nix | APK / Emerge / XBPS / Eopkg / Nix | [Native command audit #187](https://github.com/jameswlane/devex/issues/187) |
| Legacy RHEL | YUM (planned; no plugin) | [Plugin #104](https://github.com/jameswlane/devex/issues/104) |

Testing or implementation on these systems is deferred to the linked work;
Debian/Ubuntu validation does not verify their behavior. See the
[support matrix](/platforms) for optional managers and package-file methods.
Desktop plugin availability does not guarantee every theme or setting works;
review opt-in settings and the [consent requirements #271](https://github.com/jameswlane/devex/issues/271).
