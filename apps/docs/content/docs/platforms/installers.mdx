# Installer Reference

Use the [support matrix](/platforms) as the source of support levels.
A manager named in YAML must have an implemented plugin compatible with the
host. Metadata capability flags describe intent; they are not proof of native
lifecycle validation.

## Debian / Ubuntu

APT is the stable installation path. Flatpak and Snap are optional experimental
integrations. Language tools may use mise or pip; containers may use Docker;
direct scripts may use curlpipe. These methods depend on the configured
application and host prerequisites, and are not interchangeable fallbacks for
every package.

```bash
# Preview configured applications and their installation actions
devex install --dry-run

# Read the plan as JSON
devex install --dry-run --format json
```

Choose applications from your configuration/catalog. Review the plan and setup
confirmation, including dependencies and configuration writes, before approving
installation. Selecting an application does not authorize unrelated software,
repositories, shell files or desktop changes; see
[consent rules #271](https://github.com/jameswlane/devex/issues/271).

## Experimental and planned managers

DNF, Pacman, Yay, Zypper, Homebrew and the other implemented managers are listed
with limitations and tracking links in the [matrix](/platforms).
Mac App Store, MacPorts, winget, Chocolatey, Scoop and YUM have no plugins yet;
do not use them as DevEx installation methods until their linked work lands.
Native platform implementation and testing belong to those roadmap issues.

See [Linux](/platforms/linux), [macOS](/platforms/macos) and
[Windows](/platforms/windows) for platform-specific status.
