# Windows Support

Native Windows package management is **experimental** through the
[winget plugin](https://github.com/jameswlane/devex/tree/main/packages/package-manager-winget).
Chocolatey and Scoop are **planned**: Windows entries that use those methods
describe intended installers, not working ones.

## Prepare Windows

These steps assume Windows 10 1809 or later (the minimum for winget) or
Windows 11. Set up these prerequisites on a fresh machine before running DevEx:

- **winget (App Installer).** Install or update **App Installer** from the
  Microsoft Store.
- **PowerShell.** Windows PowerShell 5.1 works for the installer script.
  PowerShell 7 (`pwsh`) is recommended for daily use.
- **Windows Terminal.** Recommended (`wt`) for UTF-8 output and modern TUI
  rendering.
- **Developer Mode.** Required so non-admin processes can create symlinks.
  Search Windows Settings for **Developer Mode** and turn it on.
- **Win32 long paths.** Required for deep paths in Go modules and Node
  packages. Set `HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled`
  to `1` from an elevated shell.

Automating these steps inside DevEx is tracked in open issues:

- [Windows prerequisite checks in `devex setup` #623](https://github.com/jameswlane/devex/issues/623)
- [PowerShell configuration #135](https://github.com/jameswlane/devex/issues/135)
- [Windows Terminal profiles #136](https://github.com/jameswlane/devex/issues/136)
- [Git for Windows bootstrap #139](https://github.com/jameswlane/devex/issues/139)

## Develop DevEx on Windows

Run the prerequisite checker from the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\setup-dev.ps1
```

The default mode is read-only. Run it again with `-Fix` to install missing
tools and apply repo-local git settings:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\setup-dev.ps1 -Fix
```

Developer Mode and Win32 long paths write to `HKLM:` and need an elevated
shell. Re-run the `-Fix` command from an Administrator terminal to apply them.
After installing Git or `mise`, open a new shell so `PATH` picks it up, then
run the `-Fix` command again.

### Line endings and toolchain

The root `.gitattributes` file (added in
[#622](https://github.com/jameswlane/devex/pull/622)) forces LF line endings
for Go, YAML, and shell scripts, and CRLF only for `.ps1`, `.psm1`, `.bat`, and
`.cmd`. This prevents Git for Windows (`core.autocrlf=true`) from breaking
`gofmt`, `yamlfmt`, and Bash scripts.

Install the repository toolchain with `mise`. The repository's `.mise.toml`
doesn't pin [Task](https://taskfile.dev), so install it as well. Build and lint
the CLI from `apps/cli` through `mise exec`, which works even when mise isn't
activated in your shell:

```powershell
mise trust
mise install
mise use -g task
cd apps/cli
mise exec -- task build
mise exec -- task lint
```

### Known limitations

- Many Ginkgo test suites still fail on Windows because they invoke POSIX tools
  such as `sh` and `true` (tracked in
  [#622](https://github.com/jameswlane/devex/pull/622)).
- [Issue #621](https://github.com/jameswlane/devex/issues/621): a setup wizard
  lifecycle spec writes a stray untracked file into the checkout because of an
  unquoted Windows path.

## winget

The `package-manager-winget` plugin installs, checks, upgrades and removes
packages by exact winget identifier (`winget install --id <id> --exact`).
`devex update` runs `winget source update`, which only refreshes metadata;
`devex upgrade` upgrades only the selected packages.

DevEx does not elevate on Windows. Run it from a regular terminal for the
default and `--scope=user` installs; winget then shows a UAC prompt for any
installer that needs administrator rights, and a declined prompt is reported as
an authorization error. For `--scope=machine`, run DevEx from a terminal
opened with **Run as administrator**; this is also the form to use unattended.

```yaml
# applications/development/ripgrep.yaml
name: ripgrep
description: Fast recursive search
category: Development Tools
windows:
  install_method: winget
  install_command: BurntSushi.ripgrep.MSVC
  uninstall_command: BurntSushi.ripgrep.MSVC
```

Add `--scope machine` to `install_command` (for example
`Docker.DockerDesktop --scope machine`) to install machine-wide. The
[plugin README](https://github.com/jameswlane/devex/tree/main/packages/package-manager-winget)
lists every native command, the winget result codes DevEx interprets, and the
opt-in smoke test that installs and removes a real package.

compatibility or delivery date is promised.

## WSL

DevEx running inside WSL uses the Linux distribution's tools and support level.
Debian/Ubuntu APT support does not imply support for Windows host applications,
registry changes, PowerShell profiles or Windows package managers. WSL-specific
integration is not verified by Debian/Ubuntu container tests.

See the [Linux guide](/platforms/linux), [support matrix](/platforms)
and [consent rules #271](https://github.com/jameswlane/devex/issues/271).
