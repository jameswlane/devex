---
title: Agent Credentials
description: Supported ways to authenticate AI coding agents without storing secrets in DevEx configuration.
---

DevEx installs coding agents and diagnoses their setup, but **DevEx never prompts for, stores, or logs API keys, OAuth tokens, or other secrets**.

> **Never put secrets in DevEx configuration files.** Files under `~/.config/devex`, `~/.devex`, or shared team configuration repositories are designed to be version-controlled and inspectable. They must never contain API keys, bearer tokens, or credentials.

## Supported Ways to Provide Credentials

### 1. Vendor Interactive Login via `devex agent login`

For agents with a native OAuth or device-code login flow, hand off directly to the vendor CLI:

```sh
devex agent login claude
devex agent login codex
devex agent login copilot
devex agent login opencode
devex agent login goose
devex agent login kimi
```

DevEx attaches your terminal directly to the agent's own login subcommand and exits with its status code. Tokens are stored exclusively by the vendor CLI in its own storage location.

For Gemini CLI, launch `gemini` and run `/auth` inside an interactive session.

### 2. Environment Variables from Your Secret Manager

For API-key billing, CI/CD, or agents without an OAuth login flow (such as Aider), inject provider environment variables from your own secret manager rather than hardcoding them in shell profiles or DevEx YAML files:

- **1Password CLI**: `op run --env-file=.env.tpl -- aider`
- **Bitwarden / Vault / pass / direnv**: export keys only into the active shell or process scope

Common provider environment variable names recognized by `devex agent doctor` (checked for presence by name only; values are never printed or logged):

| Agent | Environment Variables |
| --- | --- |
| Claude Code | `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` |
| Codex CLI | `OPENAI_API_KEY`, `CODEX_API_KEY` |
| Gemini CLI | `GEMINI_API_KEY`, `GOOGLE_API_KEY` |
| GitHub Copilot CLI | `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN` |
| OpenCode | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY` |
| Goose | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_API_KEY`, `OPENROUTER_API_KEY`, `DATABRICKS_TOKEN` |
| Aider | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `DEEPSEEK_API_KEY` |
| Kimi Code | `KIMI_API_KEY`, `MOONSHOT_API_KEY`, `KIMI_MODEL_API_KEY` |

### 3. Operating System Keyring

Several agents store OAuth sessions or API keys in your operating system's native keyring (macOS Keychain, Windows Credential Manager, or Linux Secret Service via `libsecret`):

- **Claude Code** uses the OS keyring on macOS and falls back to `~/.claude/.credentials.json` (mode `0600`) on Linux or headless hosts.
- **Codex CLI** supports OS keyring storage or `$CODEX_HOME/auth.json` (default `~/.codex/auth.json`).
- **GitHub Copilot CLI** stores OAuth tokens in the OS keyring when available.
- **Goose** stores provider keys in the OS keyring by default, falling back to `~/.config/goose/secrets.yaml` on headless hosts or when `GOOSE_DISABLE_KEYRING=1`.

## Verifying Setup Safely

Run [`devex agent doctor`](/docs/cli-reference/agent-doctor) to check login status, `PATH` shadowing, Node.js version, sandbox prerequisites, and MCP configuration syntax:

```sh
devex agent doctor
devex agent doctor --format json
```

`devex agent doctor` only inspects status command exit codes, file presence via `stat`, and environment variable names. Credential files are never read, and any known API-key environment variable values are redacted from output as defense in depth.
